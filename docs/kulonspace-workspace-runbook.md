# kulonspace.com — Google Workspace, end to end

Goal: `sergey@kulonspace.com` sends and receives properly, and everything
lands in the existing `prokofiev.sv@gmail.com` inbox so there is only one
inbox to watch.

Five phases. Do them in order — phase 2 fails if phase 1 hasn't finished.

DNS records all go to:
<https://vercel.com/spokofyevs-projects/~/domains/kulonspace.com> → **DNS** tab.
Leave the Name field blank for apex (`@`) records.

---

## Phase 1 — Verify the domain

Add **one** record (either works; TXT is simpler):

| Type | Name | Value |
|------|------|-------|
| TXT | *(blank)* | `google-site-verification=…` |
| *or* CNAME | `kgvym7lbufjn` | `gv-7k55ngncarnqhy.dv.googlehosted.com` |

Copy the token with **Google's copy button**. Never retype it.

Then tick the confirmation box in the Workspace console and press **Confirm**.
If it fails, wait five minutes and retry — DNS needs to propagate.

---

## Phase 2 — Route mail to Google

| Type | Name | Value | Priority |
|------|------|-------|----------|
| MX | *(blank)* | `smtp.google.com` | `1` |

There must be no other MX records. The zone is currently empty, so there is
nothing to remove.

Mail to `sergey@kulonspace.com` starts arriving in the Workspace inbox once
this propagates.

---

## Phase 3 — Authentication (do not skip)

Without these, outbound mail lands in spam.

**SPF**

| Type | Name | Value |
|------|------|-------|
| TXT | *(blank)* | `v=spf1 include:_spf.google.com ~all` |

**DKIM** — generated by Google, so it must be done in the console first:

1. admin.google.com → **Apps** → **Google Workspace** → **Gmail** →
   **Authenticate email**
2. Select `kulonspace.com`, choose 2048-bit, **Generate new record**
3. Google shows a TXT record, host `google._domainkey`. Add it in Vercel.
4. Wait a few minutes, then press **Start authentication** in the console.

**DMARC**

| Type | Name | Value |
|------|------|-------|
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:sergey@kulonspace.com` |

`p=none` monitors without rejecting. After two weeks of clean reports,
tighten to `p=quarantine`, then `p=reject`. Starting at `p=reject` on a new
domain risks silently destroying legitimate mail.

## Phase 4 — Forward Workspace into the personal Gmail

Sign into Gmail **as `sergey@kulonspace.com`**:

1. Settings (gear) → **See all settings** → **Forwarding and POP/IMAP**
2. **Add a forwarding address** → `prokofiev.sv@gmail.com` → Next → Proceed
3. Google emails a confirmation link to `prokofiev.sv@gmail.com`. Open it there.
4. Back in the Workspace settings, select **Forward a copy of incoming mail
   to** and pick **keep Gmail's copy in the Inbox**.
5. **Save Changes** at the bottom — easy to miss, and nothing applies without it.

Keeping the copy means Workspace retains the full archive even though you read
mail in the personal inbox.

> If the forwarding option is greyed out: admin.google.com → Apps → Google
> Workspace → Gmail → **End User Access** → enable **Automatic forwarding**.

---

## Phase 5 — Send as the domain from the personal Gmail

This is the fiddly phase. It needs an App Password, which needs 2-Step
Verification on the Workspace account first.

**5a. Enable 2SV** on `sergey@kulonspace.com` at
<https://myaccount.google.com/signinoptions/two-step-verification>

**5b. Generate an App Password** at
<https://myaccount.google.com/apppasswords> — name it "Gmail send-as".
Copy the 16-character string. It is shown once.

**5c. Add the identity.** Sign into `prokofiev.sv@gmail.com`:

1. Settings → **Accounts and Import** → **Send mail as** → **Add another
   email address**
2. Name: how you want it to appear. Email: `sergey@kulonspace.com`.
   Leave **Treat as an alias** ticked.
3. SMTP settings:
   - Server: `smtp.gmail.com`
   - Port: `587`
   - Username: `sergey@kulonspace.com`
   - Password: the App Password from 5b (not the account password)
   - **Secured connection using TLS**
4. Google sends a verification code to `sergey@kulonspace.com` — which now
   forwards to the personal inbox, so it arrives where you are. Enter it.

**5d.** Optionally set `sergey@kulonspace.com` as the default From address,
and set **Reply from the same address the message was sent to**.

Works in the Gmail mobile app too — the From field becomes a picker.

---

## Simpler alternative

Phase 5 exists only to get one inbox with the right reply address. If the App
Password dance is annoying, skip phases 4 and 5 entirely and **add the
Workspace account as a second account in the Gmail app**. Two inboxes, but
native, no app passwords, no SMTP config, and nothing to break when Google
changes its security policies.

Honest assessment: the second option is more robust. The first is nicer daily
if the domain address is mainly outward-facing and low volume.

## Verification

```bash
dig TXT kulonspace.com +short
dig MX  kulonspace.com +short
dig TXT _dmarc.kulonspace.com +short
dig TXT google._domainkey.kulonspace.com +short
```

Then send a test message from `sergey@kulonspace.com` to an outside address
and check the received headers show `spf=pass` and `dkim=pass`.
